# 나노약품물리연구실 웹사이트

교수님이 연구 결과와 수업 자료를 올리고, 승인된 대학원생이 글과 댓글로 토론하는 연구실 웹사이트입니다.

- **홈(연구실 소개)과 로그인 화면**은 누구나 볼 수 있습니다.
- **연구 · 수업자료 · 토론 게시판**은 교수님이 승인한 구성원만 볼 수 있습니다.
- 로그인은 **Google 계정**으로 합니다.
- 비용이 들지 않도록 **Firebase 무료 요금제(Spark)** 와 **Netlify 무료 요금제**만 사용합니다.

> **Firebase를 연결하기 전에도 사이트가 열립니다.**
> 설정값이 없으면 화면 맨 위에 노란 "Firebase 미설정 모드" 안내가 뜨고, 샘플 글로 모든 화면을 **읽기 전용**으로 둘러볼 수 있습니다.
> 4~9단계를 마치면 코드를 고치지 않아도 실제 게시판으로 바뀝니다.

## 1. 내 컴퓨터에서 실행해 보기

> 이 단계는 **선택 사항**입니다. 바로 인터넷에 올리려면 2단계로 넘어가세요.

1. [Node.js 공식 사이트](https://nodejs.org/ko)에서 **LTS** 버전(22 이상)을 내려받아 설치합니다. 설치 화면에서는 계속 "다음"만 누르면 됩니다.
2. 이 저장소의 GitHub 페이지에서 초록색 **Code** 버튼 → **Download ZIP**을 눌러 내려받고 압축을 풉니다.
3. 터미널을 엽니다.
   - Windows: 시작 메뉴에서 **명령 프롬프트** 또는 **PowerShell**
   - Mac: **응용 프로그램 → 유틸리티 → 터미널**
4. 터미널에서 압축을 푼 폴더로 이동합니다. `cd `(끝에 공백 포함)를 입력한 뒤 폴더를 터미널 창에 끌어다 놓고 Enter를 누르면 됩니다.
5. 필요한 프로그램을 설치합니다. (처음 한 번만, 1~2분 걸립니다)
   ```bash
   npm install
   ```
6. 사이트를 실행합니다.
   ```bash
   npm run dev
   ```
7. 인터넷 브라우저에서 <http://localhost:5173> 을 엽니다. 노란 "Firebase 미설정 모드" 안내와 함께 샘플 화면이 보이면 성공입니다.
8. 끝내려면 터미널에서 `Ctrl + C`를 누릅니다.

> **(선택) 내 컴퓨터에서도 실제 Firebase에 연결하려면**
> 4~7단계를 마친 뒤 `.env.example` 파일을 복사해 이름을 `.env.local`로 바꾸고, `=` 뒤에 Firebase 설정값을 채웁니다.
> 그리고 6단계의 승인 도메인에 `localhost`가 있는지 확인하세요. (기본으로 들어 있습니다)
> `.env.local`은 GitHub에 올라가지 않도록 설정되어 있습니다.

## 2. GitHub 저장소에 올리기

> 이 코드는 이미 `sypark200/261028-NanoPharm` 저장소에 올라가 있습니다. 같은 저장소를 쓰신다면 3단계로 넘어가세요.
> 아래는 다른 저장소에 새로 올리거나, 내 컴퓨터에서 고친 내용을 올릴 때의 방법입니다.

가장 쉬운 방법은 **GitHub Desktop** 프로그램을 쓰는 것입니다.

1. [GitHub](https://github.com)에 가입하고 로그인합니다.
2. [GitHub Desktop](https://desktop.github.com/)을 설치하고 GitHub 계정으로 로그인합니다.
3. **새 저장소에 올릴 때**
   1. GitHub Desktop에서 **File → Add local repository**를 누르고 이 프로젝트 폴더를 고릅니다.
   2. "이 폴더는 저장소가 아닙니다"라는 안내가 나오면 **create a repository**를 누르고 **Create repository**를 누릅니다.
   3. 오른쪽 위 **Publish repository**를 누릅니다. "Keep this code private"는 체크해 두어도 됩니다.
4. **이미 있는 저장소에 수정 내용을 올릴 때**
   1. 왼쪽 아래 Summary 칸에 무엇을 바꿨는지 짧게 적습니다. (예: `연구실 소개 수정`)
   2. **Commit to main**을 누른 뒤 위쪽 **Push origin**을 누릅니다.

> `node_modules`, `dist`, `.env.local`은 자동으로 제외되므로 신경 쓰지 않아도 됩니다.

## 3. Netlify에 연결해 배포하기

1. [Netlify](https://www.netlify.com/)에 접속해 **Sign up → GitHub로 가입**합니다.
2. 대시보드에서 **Add new project → Import an existing project**를 누릅니다. (화면에 따라 *Add new site*라고 보일 수 있습니다)
3. **GitHub**를 고르고, 권한을 묻는 창이 뜨면 허용합니다.
4. 저장소 목록에서 **261028-NanoPharm**을 고릅니다. 목록에 없으면 아래쪽 **Configure the Netlify app on GitHub**를 눌러 이 저장소 접근을 허용합니다.
5. 설정 화면에서 아래 값을 확인합니다. 이 프로젝트의 `netlify.toml` 파일 덕분에 대부분 자동으로 채워져 있습니다.
   - **Branch to deploy**: `main`
   - **Build command**: `npm run build`
   - **Publish directory**: `dist`
6. **Deploy**를 누릅니다. 1~2분 뒤 `https://무작위이름.netlify.app` 같은 주소가 생깁니다.
7. 주소를 열어 노란 "Firebase 미설정 모드" 안내와 샘플 화면이 보이면 **1차 배포 성공**입니다.
8. (선택) 주소를 바꾸려면 **Project configuration → General → Project details → Change project name**에서 이름을 바꿉니다. 예를 들어 `nanopharm-lab`으로 바꾸면 주소가 `https://nanopharm-lab.netlify.app`이 됩니다.

> 📝 **이 Netlify 주소를 메모해 두세요.** 6단계에서 사용합니다.
>
> 이후에는 GitHub에 코드를 올릴 때마다 Netlify가 **자동으로 다시 배포**합니다.
> `public/_redirects` 파일이 들어 있어서 `/research` 같은 주소에서 새로고침해도 "Page not found"가 나지 않습니다.

## 4. Firebase 프로젝트 만들기

1. [Firebase 콘솔](https://console.firebase.google.com/)에 Google 계정으로 로그인합니다.
2. **프로젝트 만들기**(또는 *Firebase 프로젝트 시작하기*)를 누릅니다.
3. 프로젝트 이름을 입력합니다. (예: `nanopharm-lab`)
4. Gemini, Google 애널리틱스 사용 여부를 물으면 **사용 안 함**으로 두어도 됩니다. → **프로젝트 만들기**를 누릅니다.
5. **무료 요금제(Spark)인지 확인합니다.**
   - 왼쪽 메뉴 아래쪽(또는 위쪽 프로젝트 이름 옆)에 **Spark** 또는 **무료**라고 적혀 있으면 됩니다.
   - **"업그레이드" / "Blaze" 버튼은 누르지 마세요.** 이 사이트는 무료 요금제 기능만 쓰도록 만들어져 있습니다.
   - 결제 카드를 등록하라는 화면이 나오면 진행하지 말고 닫으세요.
6. 웹 앱을 등록합니다.
   1. 프로젝트 첫 화면에서 **`</>` 모양(웹) 아이콘**을 누릅니다. (안 보이면 왼쪽 위 ⚙️ **프로젝트 설정 → 일반 → 내 앱 → 앱 추가 → 웹**)
   2. 앱 닉네임을 입력합니다. (예: `lab-web`)
   3. **"Firebase 호스팅도 설정합니다"는 체크하지 마세요.** (호스팅은 Netlify를 씁니다)
   4. **앱 등록**을 누릅니다.
7. 화면에 아래와 비슷한 설정값이 나타납니다. **이 화면을 열어 두거나 메모장에 복사해 두세요.** 9단계에서 사용합니다.
   ```js
   const firebaseConfig = {
     apiKey: "AIza....",
     authDomain: "nanopharm-lab.firebaseapp.com",
     projectId: "nanopharm-lab",
     storageBucket: "nanopharm-lab.firebasestorage.app",
     messagingSenderId: "1234567890",
     appId: "1:1234567890:web:abcd1234"
   };
   ```
   나중에 다시 보려면 ⚙️ **프로젝트 설정 → 일반 → 내 앱** 아래 **SDK 설정 및 구성 → 구성**을 누르면 됩니다.

> 이 값들은 웹사이트에 공개되어도 괜찮은 값입니다. 실제 보호는 8단계의 **보안 규칙**이 담당합니다.

6. **저장**을 누릅니다. Google 옆에 "사용 설정됨"이 보이면 완료입니다.

5. 나중에 Netlify 주소를 바꾸거나 별도 도메인을 연결하면, 그 주소도 같은 방법으로 추가합니다.

## 7. Firestore 데이터베이스 만들기

1. 왼쪽 메뉴 **빌드 → Firestore Database**를 누릅니다.
2. **데이터베이스 만들기**를 누릅니다.
3. 버전(Edition)을 물으면 **Standard**를 고릅니다.
4. 데이터베이스 ID는 기본값 `(default)` 그대로 둡니다.
5. 위치는 **`asia-northeast3 (Seoul)`** 을 고릅니다. **위치는 나중에 바꿀 수 없습니다.**
6. 보안 규칙 시작 방식은 **프로덕션 모드로 시작**을 고릅니다. (바로 다음 단계에서 규칙을 바꿉니다)
7. **만들기**를 누르고 잠시 기다립니다.

### 7-1. 색인(index) 만들기

게시판 목록을 "최신 글 순"으로 불러오려면 색인 2개가 필요합니다.

1. Firestore Database 화면 위쪽의 **색인(Indexes)** 탭 → **복합(Composite)** → **색인 만들기**를 누릅니다.
2. **첫 번째 색인**
   - 컬렉션 ID: `posts`
   - 필드 1: `category` — **오름차순**
   - 필드 2: `createdAt` — **내림차순**
   - 쿼리 범위: **컬렉션**
   - **만들기**를 누릅니다.
3. **두 번째 색인** (수업자료의 과목 필터용)
   - 컬렉션 ID: `posts`
   - 필드 1: `category` — **오름차순**
   - 필드 2: `tags` — **배열 포함(Arrays)**
   - 필드 3: `createdAt` — **내림차순**
   - 쿼리 범위: **컬렉션**
   - **만들기**를 누릅니다.
4. 상태가 "사용 설정됨"으로 바뀔 때까지 몇 분 기다립니다.

> **더 쉬운 방법:** 색인을 만들지 않고 사이트를 쓰면 게시판에 *"Firestore 색인(index)이 필요합니다"* 라는 오류와 함께 **링크**가 나타납니다.
> 그 링크를 누르면 필요한 색인이 미리 채워진 화면이 열리므로 **저장**만 누르면 됩니다. 몇 분 뒤 다시 시도하면 됩니다.

## 8. 보안 규칙 붙여넣고 게시하기

보안 규칙은 "누가 무엇을 읽고 쓸 수 있는지"를 정하는 **가장 중요한 설정**입니다.

1. 이 저장소의 [`firestore.rules`](./firestore.rules) 파일을 엽니다. GitHub에서 열었다면 오른쪽 위 **복사 아이콘(Copy raw file)** 을 누르면 전체가 복사됩니다.
2. Firebase 콘솔 **Firestore Database → 규칙(Rules)** 탭을 엽니다.
3. 편집기에 있던 내용을 **모두 지우고**(`Ctrl + A` → `Delete`) 복사한 내용을 붙여넣습니다.
4. **게시(Publish)** 를 누릅니다.
5. 빨간 오류 표시 없이 게시되면 완료입니다. 1분 정도 지나면 적용됩니다.

이 규칙이 하는 일 (자세한 설명은 파일 맨 위 주석에 있습니다):
- 처음 로그인한 사람은 **승인 대기(pending)** 상태로만 가입됩니다.
- 누구도 **스스로 권한을 올릴 수 없고**, 권한 변경은 관리자만 할 수 있습니다.
- 게시판과 댓글은 **승인된 회원만** 읽을 수 있습니다.
- **연구·수업자료** 글은 관리자만, **토론** 글은 회원도 쓸 수 있습니다.
- 글과 댓글은 **쓴 사람 본인 또는 관리자만** 수정·삭제할 수 있습니다.

> `firestore.rules` 파일을 수정한 경우에는 이 단계를 다시 해야 콘솔에 반영됩니다.

## 9. Netlify에 Firebase 설정값 넣고 재배포하기

1. [Netlify](https://app.netlify.com/)에서 이 사이트를 엽니다.
2. **Project configuration(또는 Site configuration) → Environment variables**로 갑니다.
3. **Add a variable → Import from a .env file**을 누릅니다.
4. 아래 내용을 붙여넣고, 각 `=` 뒤를 4단계 7번의 값으로 바꿉니다. **따옴표는 넣지 마세요.**
   ```
   VITE_FIREBASE_API_KEY=AIza....
   VITE_FIREBASE_AUTH_DOMAIN=nanopharm-lab.firebaseapp.com
   VITE_FIREBASE_PROJECT_ID=nanopharm-lab
   VITE_FIREBASE_STORAGE_BUCKET=nanopharm-lab.firebasestorage.app
   VITE_FIREBASE_MESSAGING_SENDER_ID=1234567890
   VITE_FIREBASE_APP_ID=1:1234567890:web:abcd1234
   ```
   | Netlify 변수 이름 | Firebase 설정값 |
   |---|---|
   | `VITE_FIREBASE_API_KEY` | `apiKey` |
   | `VITE_FIREBASE_AUTH_DOMAIN` | `authDomain` |
   | `VITE_FIREBASE_PROJECT_ID` | `projectId` |
   | `VITE_FIREBASE_STORAGE_BUCKET` | `storageBucket` |
   | `VITE_FIREBASE_MESSAGING_SENDER_ID` | `messagingSenderId` |
   | `VITE_FIREBASE_APP_ID` | `appId` |
5. **Import variables**를 누릅니다.
6. **환경변수는 다시 배포해야 적용됩니다.** **Deploys** 메뉴 → **Trigger deploy → Deploy project**(또는 *Deploy site*)를 누릅니다.
7. 1~2분 뒤 사이트를 새로고침합니다. **노란 "Firebase 미설정 모드" 안내가 사라졌으면 연결 성공**입니다.

> 앞의 네 값(API_KEY, AUTH_DOMAIN, PROJECT_ID, APP_ID) 중 하나라도 비어 있으면 계속 미설정 모드로 동작합니다.

## 10. 처음 로그인한 뒤 본인을 관리자(admin)로 바꾸기

처음 로그인한 사람은 누구든 "승인 대기" 상태입니다. 교수님 계정은 Firebase 콘솔에서 **한 번만** 직접 관리자로 바꿉니다.

1. 사이트 오른쪽 위 **로그인 → Google 계정으로 로그인**을 눌러 교수님 계정으로 로그인합니다.
2. "승인 대기 중입니다" 화면이 나오면 정상입니다.
3. Firebase 콘솔 **Firestore Database → 데이터(Data)** 탭을 엽니다.
4. 가운데 열의 **`users`** 컬렉션을 누릅니다.
5. 문서 목록(알 수 없는 영문·숫자 조합) 중에서 오른쪽 내용의 `email`이 **교수님 이메일인 문서**를 찾아 누릅니다.
6. 오른쪽 필드 목록에서 **`role`** 위에 마우스를 올리고 **연필(수정) 아이콘**을 누릅니다.
7. 값 `pending`을 지우고 **`admin`** 이라고 입력합니다. (소문자, 따옴표 없이)
8. **업데이트(Update)** 를 누릅니다.
9. 사이트로 돌아가 **새로고침**합니다. 상단 메뉴에 **회원 관리**가 보이면 성공입니다.

> 다른 사람을 관리자로 만들 때도 같은 방법을 씁니다. 사이트의 회원 관리 화면에서는 관리자를 지정할 수 없습니다(안전을 위해서입니다).

## 11. 학생 승인하기

1. 학생에게 사이트 주소를 알려 주고 **Google 계정으로 로그인**하도록 안내합니다. 학생은 "승인 대기 중" 화면을 보게 됩니다.
2. 교수님 계정으로 사이트에 로그인한 뒤 상단 메뉴 **회원 관리**를 누릅니다.
3. **승인 대기** 목록에서 학생 이름과 이메일을 확인하고 **승인**을 누릅니다. 확인 창에서 **확인**을 누릅니다.
4. 학생이 승인 대기 화면에서 **새로고침**을 누르면 게시판을 이용할 수 있습니다.
5. 졸업 등으로 접근을 막으려면 **회원** 목록에서 **권한 해제**를 누릅니다. 그 학생은 다시 승인 대기 상태가 됩니다.

> 처음 보는 이메일이 승인 대기에 있으면 승인하지 마세요. 승인하지 않은 사람은 게시판을 전혀 볼 수 없습니다.

## 12. 연구실 소개 문구 수정하기

홈 화면의 연구실 이름, 소개, 연구 분야, 연락처, 수업자료 과목 목록은 모두 **[`src/content/lab.ts`](./src/content/lab.ts)** 파일 하나에 있습니다.

**GitHub 웹사이트에서 바로 고치는 방법 (가장 쉬움)**

1. GitHub에서 이 저장소를 열고 `src` → `content` → `lab.ts` 순서로 누릅니다.
2. 오른쪽 위 **연필 아이콘(Edit this file)** 을 누릅니다.
3. **작은따옴표(`'...'`) 안의 글자만** 바꿉니다. 따옴표, 쉼표, 괄호는 지우지 마세요.
   ```ts
   name: '나노약품물리연구실',          // ← 따옴표 안만 바꾸기
   professor: '홍길동 교수',
   ```
   - 소개 문단(`intro`)이나 연구 분야(`researchAreas`)를 늘리려면, 기존 항목 하나를 쉼표까지 통째로 복사해 바로 아래에 붙여넣고 글자를 바꿉니다.
   - 문구 안에 작은따옴표(`'`)를 써야 하면 `\'`처럼 앞에 역슬래시를 붙입니다.
   - `tagline`은 홈 화면 남색 대표 영역의 연구실 이름 아래에 보이는 한 줄 문구입니다.
   - 연락처 중 표시하고 싶지 않은 항목은 `''`(빈 따옴표)로 두면 숨겨집니다.
   - `courses`(과목 목록)에 적은 이름은 수업자료 글의 **태그와 똑같이** 적어야 과목 필터에 맞게 걸러집니다.
4. 오른쪽 위 **Commit changes…** → 다시 **Commit changes**를 누릅니다.
5. Netlify가 자동으로 다시 배포합니다. 1~2분 뒤 사이트를 새로고침하면 바뀐 내용이 보입니다.

> 저장 후 사이트가 바뀌지 않으면 Netlify **Deploys** 화면에서 빨간 "Failed"가 있는지 확인하세요. 대부분 따옴표나 쉼표가 지워진 경우입니다. GitHub에서 파일의 **History**를 눌러 이전 내용과 비교해 보세요.

| 할 일 | 누가 | 어디서 |
|---|---|---|
| 연구 결과 올리기 | 교수(admin) | 연구 → 새 글 쓰기 |
| 수업 자료 올리기 | 교수(admin) | 수업자료 → 새 글 쓰기 (태그에 과목명 입력) |
| 토론 글 쓰기 | 교수, 학생(member) | 토론 → 새 글 쓰기 |
| 댓글 쓰기 | 교수, 학생 | 글 아래 댓글 칸 |
| 파일 공유 | 교수, 학생 | 파일을 Google Drive·OneDrive에 올리고 **공유 링크**를 글의 "첨부 링크"에 추가 |

- 본문은 **마크다운** 문법을 씁니다. `## 소제목`, `**굵게**`, `- 목록`, `| 표 |` 등을 쓸 수 있고, 글쓰기 화면의 **미리보기** 탭에서 결과를 확인할 수 있습니다.

## 자주 생기는 문제

| 증상 | 해결 방법 |
|---|---|
| 노란 "Firebase 미설정 모드" 안내가 계속 보임 | 9단계의 변수 이름이 정확한지(앞에 `VITE_`가 붙었는지) 확인하고 **다시 배포**하세요. |
| 로그인할 때 `api-key-not-valid` 또는 "API 키가 올바르지 않습니다" 오류 | Netlify 환경변수 `VITE_FIREBASE_API_KEY`의 값을 지우고, Firebase 콘솔의 `apiKey` 값(AIza로 시작하는 39글자)만 다시 붙여넣은 뒤 **다시 배포**하세요. 따옴표·쉼표는 넣지 않습니다. |
| 로그인할 때 "승인 도메인" 오류 | 6단계에서 Netlify 주소를 `https://` 없이 추가했는지 확인하세요. |
| 로그인할 때 "Google 로그인이 켜져 있지 않습니다" | 5단계를 확인하세요. |
| 로그인 창이 뜨지 않음 | 브라우저의 팝업 차단을 이 사이트에 대해 해제하세요. |
| "권한이 없습니다" 오류 | 8단계 보안 규칙을 게시했는지, 승인된 회원인지 확인하세요. |
| "Firestore 색인(index)이 필요합니다" | 오류 속 링크를 눌러 색인을 만들고 몇 분 기다리세요. (7-1단계) |
| 승인했는데 학생이 계속 승인 대기 화면 | 학생에게 **새로고침**하도록 안내하세요. |
| `/research` 등에서 새로고침하면 Netlify 404 | `public/_redirects` 파일이 저장소에 있는지 확인하세요. |

**무료 사용량 참고:** Firebase Spark 요금제는 하루에 문서 읽기 5만 회, 쓰기 2만 회까지 무료입니다. 연구실 규모에서는 넉넉한 양입니다. 이 사이트는 목록을 20개씩 나눠 불러오고 실시간 연결을 쓰지 않아 읽기 횟수를 아낍니다. 한도를 넘으면 돈이 나가는 것이 아니라 그날 하루 사용이 멈춥니다.
